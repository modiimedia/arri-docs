To make the most of Arri RPC, it helps to understand the underlying mechanisms that make its instant, cross-language generation possible.

---

## 1. Code-First vs. Schema-First

Traditional RPC solutions (like gRPC) require you to write `.proto` schema files before you write your server code. You write a contract, compile it to stubs, then write the implementation:

```
Contract (.proto) ──> Compile ──> Server Implementation & Client Callers
```

Arri RPC reverses this flow. You write standard server-side endpoints directly in TypeScript, Go, or Rust. The type schemas and procedural endpoints are derived straight from your native structures. 

```
Server Code (JS/TS, Go, or Rust) ──> Auto-Derived App Spec ──> Client Codegen
```

This guarantees that **your server implementation is always the single source of truth**.

---

## 2. The Arri App Definition (AAD)

The cornerstone of Arri RPC is the **Arri App Definition (AAD)**. This is a lightweight JSON contract generated dynamically by the server. 

When your server compiles or starts, it outputs a JSON object structure that looks like this:

```json
{
  "schemaVersion": "0.0.1",
  "procedures": {
    "getUser": {
      "transport": "http",
      "method": "get",
      "path": "/users/get-user",
      "params": "GetUserParams",
      "response": "User"
    }
  },
  "definitions": {
    "GetUserParams": {
      "properties": {
        "userId": { "type": "string" }
      }
    },
    "User": {
      "properties": {
        "id": { "type": "string" },
        "name": { "type": "string" }
      }
    }
  }
}
```

The AAD maps all available procedures (RPC routes), their methods (HTTP, Websocket, SSE), and references the parameter and response objects, which are written in JTD.

---

## 3. JSON Type Definition (JTD)

Rather than using complex JSON Schema (which is highly flexible but difficult to compile across multiple programming languages efficiently), Arri standardizes its data types on **JSON Type Definition (RFC 8927)**.

JTD restricts the schema vocabulary to a strict, predictable set of primitives (e.g. `string`, `float64`, `int32`, `timestamp`, `boolean`, `array`, `properties`). Because JTD maps perfectly to typed structs or classes in languages like Rust, Dart, and Go, client generators can emit exceptionally clean and readable native structures with zero ambiguity.

---

## 4. Server-Sent Events (SSE)

Unlike traditional APIs that require WebSockets for streaming (which adds state management and reconnect complexity), Arri features native, first-class support for **Server-Sent Events (SSE)**. 

If you define a streaming procedure, Arri handles it over high-performance HTTP event-streams. Client generators automatically emit observable or asynchronous stream handlers in their respective languages, making real-time features like chat or live metrics incredibly easy to build.
